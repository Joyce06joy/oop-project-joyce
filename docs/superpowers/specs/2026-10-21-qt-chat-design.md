## 4. 用户流程与界面

启动页提供登录、注册、演示说明。主窗口左侧为消息、联系人、群和待办入口，顶部显示当前账号、服务切换及连接状态。个人资料、改密、开通服务及微信绑定有明确入口。

消息页展示会话列表、未读数、聊天正文、输入区、发送按钮与发送状态。联系人页提供搜索、申请、备注和删除。群页提供我的群、发现群、成员与管理操作。危险操作在客户端确认后提交，服务端按当时权限执行。

客户端不显示数据库路径、内部异常堆栈、协议字段等实现细节；启动故障提供简明原因和重试入口，技术详情进入本地诊断日志，日志不记录密码或完整消息正文。

默认只需启动客户端。它先连接本机服务；连接不存在时尝试启动同目录服务端，再等待就绪。多个客户端同时启动时，只允许一个服务端成功监听，其他启动尝试退出并重新连接现有服务。握手校验应用及协议版本，端口被其他程序占用时明确报错。服务端支持单独启动以便测试；默认仅监听回环地址，不监听局域网。

服务端启动后由本次本地演示会话共用；关闭一个客户端不终止服务端或其他窗口。提供显式“结束本地演示服务”入口，确认影响后停止接收新操作、完成在途提交、断开客户端并退出。客户端退出不执行隐式数据库保存。

## 5. 模块与接口边界

| 模块及代表类 | 职责与依赖 |
|---|---|
| 客户端窗口、页面和模型 | 处理输入、显示数据、维护短暂界面状态；依赖客户端接口，不直接读写数据库 |
| `ClientConnectionDXX` | 管理连接、请求响应匹配、推送、断线和超时；使用 Qt Network 与协议编解码 |
| `ProtocolCodecDXX` | 有界接收缓存、帧解析与编码、基础消息结构校验；不执行业务 |
| `ChatServerDXX`、`SessionDXX` | 接受连接、绑定登录身份、检查握手、分发请求与推送；每条连接有独立会话 |
| `ApplicationDXX` | 串行执行带明确操作身份的业务，统一查询权限和事务提交；返回结果及提交后事件 |
| `PlatformDXX` 及领域对象 | 维护共享账号、好友、群、消息规则；不再持有全局当前用户；依赖明确传入的业务上下文 |
| `StorageDXX` 及 SQLite 封装 | 保存、加载、事务、版本迁移与唯一约束；只在持有它的业务线程使用 |
| 密码验证工作对象 | 执行耗时密码派生与验证，向业务线程返回结果；不持有数据库连接或可变平台引用 |

可按职责增加辅助类，但不能把协议、窗口、业务和存储堆在同一文件。窗口持有 ID 和展示副本，不长期保存可能随事务替换而失效的领域引用。

登录身份由服务端会话确定，客户端不能通过请求中的 sender 字段冒充其他用户。连接关闭即撤销该连接会话；同一账号可在多个窗口登录，各连接独立确认服务，密码修改后撤销该账号其他连接并要求重新登录。

## 6. 线程、状态和事务

客户端主线程处理 Qt 界面及异步网络事件，不执行阻塞等待、密码派生或数据库操作。服务端网络线程接收、解析与发送数据。单独的业务工作线程拥有平台状态和 SQLite 连接，顺序处理业务，避免多个窗口互相覆盖快照。跨线程用 Qt 信号和数据副本传递，不跨线程直接操作窗口、Socket 或数据库对象。

注册和认证所需密码计算交给受限工作池。验证开始时只提取必要的凭据副本；返回时在业务线程检查凭据版本与连接是否仍有效，过期结果不产生登录或改密。退出时停止接收任务，等待在途任务安全结束，再销毁对象。

保留旧版小规模候选快照事务：复制平台、执行业务、验证、SQLite 提交、发布新状态。新增聊天数据、成员区间和幂等键均纳入同一事务。快照只包含共享持久状态，会话不参与复制和落盘。提交成功后才发送成功响应和推送；失败回滚，原内存不发布。

先保留该策略以复用已验证规则；它的吞吐限制在报告中说明。客户端不各自打开 SQLite。服务端启动时锁定所选数据目录的独占应用锁，防止另一服务端在不同端口误用同一数据库；数据库修订检查继续作为保护。

## 7. 通信协议与失败处理

使用 TCP 长度帧：4 字节大端无符号长度，随后为 UTF-8 JSON。单帧上限 1 MiB；消息正文上限沿用 2000 UTF-8 字节，界面按实际字节校验并提示。长度非法、缓存超限或严重结构错误时关闭该连接，其他客户端继续工作。必须支持一个请求分多次到达、多个请求一次到达，以及发送缓冲未一次写完。

请求含协议版本、请求 ID、操作名和参数；响应含请求 ID、成功结果或稳定错误码和可读说明。推送含事件类型、服务、业务对象 ID 和刷新所需信息。首个请求为版本握手，未经认证的连接只允许握手、注册和登录。

每条发送消息携带客户端生成的 UUID，服务端按“发送人＋UUID”保存唯一映射。重试必须复用 UUID；参数一致返回原结果，参数不一致拒绝。私聊和群聊共用此幂等规则，记录与消息同事务提交，重启后仍有效。客户端发送框中的待确认 UUID 在本次进程内保留；未确认草稿跨客户端重启恢复不列入本期承诺。

发送状态为发送中、已发送、发送失败，以及断线或超时后的“结果待确认”。已发送仅表示服务端已保存，不等同对方收到或已读。结果待确认时允许用原 UUID 重试，不能生成新请求而重复落库。其他写业务不在超时后自动重放，先重新查询状态，由用户决定再次操作。

连接中断显示离线状态并保留输入，暂时禁止新的写操作；提供重新连接并重新登录。重新登录后重新查询会话、待办和历史，以持久数据弥补错过的推送，不依赖推送完整回放。

## 8. 消息、群历史与数据库演进

私聊只允许当前服务好友发送；删除好友后保留双方此前历史，停止新的发送。离线接收者下次登录可查询已保存消息。私聊保留已读与未读能力；群聊本期以每个用户的阅读游标计算未读数，不提供逐人的已读回执列表。

群消息仅允许提交时仍在群且已确认当前服务的成员发送。QQ、微信规则切换不改变群身份、成员历史区间或消息。消息顺序以服务端提交顺序为准，时间由服务端记录，客户端不能指定权威时间。

用户确认的群历史规则：只能读取自己加入后、仍在群期间提交的消息；退出或被踢后保留这些可见历史，不再接收新消息。重新加入形成新的可见区间，离群期间消息不可见。群主和管理员同样受历史可见区间限制。

使用服务端持久化的单调事件序号表示加入、离开和消息的提交先后，避免时间戳同秒造成越权。成员区间记录 join_seq、可空 leave_seq；消息仅在 join_seq < message_seq < leave_seq（未离开则无上界）时可见。发送、离群、踢人串行提交，先后顺序唯一。一个用户可拥有多个不重叠区间；退群后保留记录。群未读与历史分页均先过滤可见区间，不能泄漏不可见消息的正文、总数或预览。

SQLite 从现有版本 2 演进至版本 3，至少包括：

- 保留旧用户、账号、好友、申请、群及成员数据。
- 消息增加目标类型（私聊/群）、群目标和事件序号；保留旧私聊 ID、正文、时间与已读含义。
- 新增群成员历史区间、客户端消息 UUID 唯一映射、群阅读游标和事件序号元数据。
- 原私聊记录转为私聊目标；现有群成员在迁移基点建立开放区间。旧版没有群消息和成员历史，不虚构迁移前入退群记录。

实现时明确外键、唯一约束、目标类型约束和编号恢复规则；不能只修改版本号。迁移在单事务中完成，先备份所选副本；失败不发布内存状态且保留原副本与备份，未知高版本拒绝打开。新建演示库直接建立最新结构。
